### 三个根因（之前几轮都判断错了，这次靠数据纠正）
1. **方盒子**：`buildFixedMap` 的 Voronoi 裁剪外框是硬编码矩形 `RECT`（index.html:3448），
   最外圈地块外侧边全落在同一直线 → 不管内部怎么抖，外轮廓永远是方的。
2. **一样大**：普通 Voronoi 用中垂线切，种子点是规则网格 ⇒ 单元面积天然均匀。
   实测「随机图(L3) 面积 CV 只有 0.127，比现状 L1 的 0.190 还小」——
   「格子有大有小」根本不是 L3 好看的原因（我前两轮方向错了）。
   真正差别在**形状不规则度**（L3 = 0.433，现状 L1 = 0.304）。
3. **连成直线**：Voronoi 相邻两块共享一整条完整直线边。

### 四处改动（均在 tests/gen-map-organic.js 里以补丁方式验证）
- ① 重画 7×7 手画网格：陆地成片集中 + 走廊密排 + 外海三面包围。
  **坑**：替换锚点必须含 `cols/rows`，只换 `grid:[...]` 会导致 rows 仍是 5、7 行被读成 5 行（V6 就这么废的）。
- ② 加权 Voronoi（Power diagram）：分界线 `|x-a|²-wa = |x-b|²-wb` 仍是直线半平面，
  所以能复用 `clipPoly` 的逐边裁剪，只把阈值从 `(|b|²-|a|²)/2` 换成带权重项。
  权重表按玩法角色给：P 0.85 / 敌营 0.55 / N 0.10 / T -0.20 / 山 -0.30 / 走廊 -0.18。
  **权重 1.0 倍差会到 10x 且 L2 跨江边掉到 2（吞格）；0.55 档位最佳**。
- ③ 共享边细分 + 噪声位移：每条边切 2 段、中间点沿法向随机偏移。
  位移只由「边的两个端点」哈希决定 ⇒ 两块算出的点逐点相同，方向相反时反序插入 ⇒ 严丝合缝。
  **巨坑**：细分点的 cache 会让点张冠李戴，多边形直接炸成锯齿（自交 15/15）。
  计算本身是纯确定性的，去掉 cache 即修复。几何自检（tests/check-geom.js）必备。
- ④ 外海碎礁过渡带。
