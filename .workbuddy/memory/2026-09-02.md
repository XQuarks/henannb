### 方法论教训（重要，写给自己看）

**`_tmp_burn.js` 里埋点用了反引号模板字面量，而整个 DRIVER 本身包在模板字符串里 → 反引号提前闭合 → 脚本 SyntaxError。而我用 `grep -q "FAIL" || 计数 0` 的方式统计，把崩溃当成了通过，产生 3 次「假通过」（60×0、200×0 等）。**

修正后的统计模板（必须带崩溃检测）：
```bash
out=$("$NODE" tests/X.js 2>&1)
if echo "$out" | grep -qE "SyntaxError|DRIVER ERROR|TypeError"; then crash=$((crash+1));
elif echo "$out" | grep -q "FAIL"; then fails=$((fails+1));
elif ! echo "$out" | grep -q "RESULT pass=N fail=0"; then crash=$((crash+1)); fi
```
任何「0 失败」的结论，都要先确认脚本真的输出了 RESULT 行。

- **根因**：`plans` 阶梯第 1 档几乎必然建图成功 → 后两档（更密）永远轮不到；`minCells` 只有 8~12 所以直接收工。逻辑缺陷在 `for(const P of plans){ if(tryBuildMap(...)) break; }`——只按「建图成败」换档，不按「够不够大」换档。
