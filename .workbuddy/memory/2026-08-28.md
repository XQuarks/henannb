## 第一批实施（黎总授权后已落地）

**改动**：`index.html` +157 / -5（仅 index.html，未动其他文件）。

**关键设计决策（踩坑记录，重要）**：
最初按提案写的是「把树状大陆裁剪成目标形状」，实测两个硬伤：
1. 原始树状大陆只有 **17 格左右**（1280×720 屏），裁掉 30% 就剩 10 格出头，地图太小；
2. 树状大陆格分布不均，按包围盒几何距离硬切经常把桥切断，成功率只有 60–75%。

**改为「让脊柱直接长成目标形状」后成功率 100%、一格不丢**：
- `genSkeleton(cx,cy,segLen,forceBranches,mode)` 新增 mode 参数
  - `mode==='M3'`：两端各一团（各自放射 6 条短枝）+ 中间细腰（A→B 连线中段密集取点）
  - `mode==='M5'`：沿屏幕长边（`W>=(H-G_TOP)` 则水平）双向直线长条，极少分叉
  - **两处都必须沿屏幕长边摆**，随机角度会生成斜的，按包围盒看是方块，没有窄长观感
- `applyTerrainShape(tpl,minD)`（新增）：记录 `SHAPE={tpl,horiz,mx,my}`，M3 再做可选收腰（失败也不影响地形成立）
- 调用顺序：塑形必须在 `buildAdjacency()` **之后**（连桥要在邻接表上跑；早期版本放前面会报 `u.adj is not iterable`）
- 桥图基地分侧：`SHAPE.tpl==='M3'` 时玩家占长轴一端（前 20% 中邻居最多的格）、两 AI 占另一端（后 25% 中最远的两个）
- `lakeBig`（步骤 8.6 新增）：从最中心向外逐格挖，`cellIsLandlocked` + `connectedCountWithout` 双校验；`sanctum` 关保护最中心格作湖心岛；严格模式挖不到时降级为「只校验不断路」

**测试环境大坑**：`tests/*.js` 的 DOM stub 里 `getBoundingClientRect()` 固定返回 `height:600`，导致 `G_TOP=Math.max(54, 604)=604`，可玩区只剩 720-604=116px，地图小到 8~14 格。新写的 `tests/e2e-terrain.js` 已修正为 `id==='hud' ? 54 : 600`。**旧测试文件仍有此问题**，只是它们的断言不依赖格子数。

**实测结果**（10 次采样）：
- 人类 L2 渡口阻击：M3 10/10 成功，28 格，长宽比 2.07
- 矮人 L8 山谷冲锋：M5 10/10 成功，16 格，长宽比 4.7
- 天龙 L8 三面合围：挖出内陆湖，祭坛落在湖心岛

**测试结果**：新增 `tests/e2e-terrain.js` 36/36；原有 7 个套件全部保持全绿（director 61、v5 60、tree 32、draft 35、flow ALL OK、camp 21、gold-smoke ALL PASS）。

## 第二批 A：桥头碉堡（黎总指定需求，已落地）

**需求**：① 桥形图区块太多，稍微减少；② 桥的部分就是一条直线的几个区块；③ 桥中右侧靠近敌人方加「碉堡」，易守难攻、自然兵力上限 10、1 兵需外来 2 兵抵消；④ 展示时加盾牌图标说明抵消能力；⑤ 调整剧情引导玩家占领碉堡。

**实现**：
- 碉堡常量 `BUNKER_CAP=10` / `BUNKER_DEF=0.5`，战斗层在 `arriveBall` 的 pow 链上追加 `if(node.bunker) pow *= BUNKER_DEF`（与矮人石肤、符文护体同层）。
- 放置：步骤 9 里 `SHAPE.tpl==='M3'` 时，从 `freeNeu().filter(onBridge)` 取 key 最大的（最靠敌端）；桥面被占满时兜底取「最靠近桥心的一批里最靠敌端」的格。
- 渲染：`drawBunker`（矮胖石堡 + 3 城齿 + 2 射击孔）+ `drawShieldBadge`（盾形 + 「×2」，画在建筑左上角避开顶部状态文字）。
- 焦点解析表新增 `focus:'bunker'`；5 个桥关台词/导演剧本改写（人类 L2、哥布林 L2、哥布林 L9 加指向碉堡的开场镜头）。

**关键踩坑（重要，下次直接照做）**：
1. **桥图格数不由团距决定，由团的体量决定**。整图适配会按包围盒等比压缩（`sc=min(availW/w, availH/h, 1.18)`），团距拉大 → 包围盒变大 → sc 变小 → 图被压扁 → 格数反而暴跌。试过 off 3.6/5.2 都掉到 8~13 格；最终 `M3_OFF=6.0` + `M3_ARM=3`（团 3 步）+ 6 枝才稳定在 10~24。
2. **两团绝不能靠太近**：挨近了中间空隙被团挤没，桥面就没格了，碉堡随之缺席。`M3_GAP` 必须 **< 团内边缘 `off - armR - keepRad`**，否则团格混进桥面。
3. **桥面压单链要用「带权最短路」而不是几何裁切或分桶**：只按跳数 BFS 会 zigzag（散布 100+）；按长轴分桶会经常断路退回两行。改成 Dijkstra、代价 `1 + |across|/minD*1.6` 后，路径自然贴中线，散布降到 45~78（< 格间距 96 即单行），且路径自带连通性。
4. **箭塔优先放割点，而桥面格全是割点** → 会把桥面占满导致碉堡没位置。已加 `notBridge()` 让塔/兵营避开桥面，桥上只留碉堡这一个硬骨头。
5. 桥形/走廊图会被裁掉一部分，`buildMap` 的最低格数门槛对 M3/M5 要从 8 抬到 10，否则会生成 8 格空壳图。

**实测**：人类 L2 23 格（原 28）、桥面 5 格、碉堡 1；矮人 L2 20 格、桥面 4 格；矮人 L8 走廊 18 格；天龙 L8 湖 3 片。
**测试**：`tests/e2e-terrain.js` 59/59；全套回归仍全绿（director 61 / v5 60 / tree 32 / draft 35 / flow / camp 21 / gold-smoke / check-ids）。
